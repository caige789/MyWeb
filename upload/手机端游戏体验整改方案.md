# 数字花园 · 手机端游戏体验整改方案（v3）

> 本文档写给接手整改的 agent。基于对 v3 代码的实际审查（`F:\CodeGame\ZCode\0827\src\components\games\`），按严重程度排序，每条含：根因 → 涉及文件/行号 → 修复方案（含代码）。
> 用户反馈：**手机端植物大战僵尸画面完全加载不出来，很多游戏画面很小、体验极差**。电脑端正常（关键线索，见问题 1）。

## 问题 1【P0 · 全局】画布逻辑坐标未缩放到显示尺寸 → 手机画面被裁剪/错位

**这是"手机端画面坏、电脑端正常"的根本原因，影响至少 6 款游戏。**

### 根因
这类游戏有一套「逻辑坐标系」（如 PvzGame `LOGIC_W=640, LOGIC_H=356`，AircraftGame 同理），**所有实体位置、绘制都按逻辑坐标**（640×356）计算。但画布的实际显示尺寸是 `min(容器宽, 640)`——手机上容器宽约 360px。代码只做了 `ctx.setTransform(dpr,0,0,dpr,0,0)`（纯 dpr 缩放），**没有把 640 逻辑宽缩放到 360 显示宽**：

- 电脑端容器宽 ≥640 → 显示 640、逻辑 640，1:1，正常 ✅
- 手机端显示 360 → 逻辑 640 的内容画进 360 宽的缓冲 → **右侧 280px（44%）全部被裁剪**，画面只显示左上角，僵尸从右侧进入直接不可见、第 6~9 列无法看到/操作 → 表现为"画面没加载出来、没法玩" ❌

### 涉及文件
| 文件 | 位置 | 问题 |
|---|---|---|
| `PvzGame.tsx` | `setupCanvas` 290-306 行、绘制循环 535 行 `setTransform(dpr)` | 逻辑 640×356，未缩放 |
| `AircraftGame.tsx` | 676-677 行 `setTransform(dpr)`、`resizeCanvas` 1235-1245 行 | 逻辑宽，未缩放 |
| `GomokuGame.tsx` | 502-511 行 | 逻辑 size，未缩放 |
| `SnakeGame.tsx` | 729-735 行 | 逻辑 size，未缩放 |
| `BreakoutGame.tsx` | 1021-1027 行 | 逻辑宽，未缩放 |
| `TetrisGame.tsx` | 绘制用逻辑坐标 | 需核对 |

### 修复方案（统一范式）
所有「逻辑坐标绘制」的游戏，transform 必须为 **`dpr × scale`**，其中 `scale = 显示宽 / 逻辑宽`：

```ts
// setupCanvas / resize 里：
const scale = displayW / LOGIC_W;          // 手机上 360/640 = 0.5625
canvas.width  = displayW * dpr;
canvas.height = displayH * dpr;            // displayH = displayW * (LOGIC_H / LOGIC_W)
canvas.style.width  = `${displayW}px`;
canvas.style.height = `${displayH}px`;
ctx.setTransform(dpr * scale, 0, 0, dpr * scale, 0, 0);   // 关键：乘 scale

// 绘制循环开头必须同样 setTransform(dpr*scale,...)，不要只 setTransform(dpr)
// 屏幕坐标 → 逻辑坐标（触摸换算）也要同一 scale：
//   logicX = (clientX - rect.left) / rect.width * LOGIC_W   ← 这个换算本身是对的，保持
```
`scale` 存进 ref（如 `scaleRef`），绘制循环每帧读取。**注意：循环里每帧 setTransform 的地方（如 PvzGame 535 行）必须同步改成 `dpr*scale`，否则 resize 后循环会覆盖掉 setupCanvas 的 transform。**

## 问题 2【P0 · PvzGame】两套坐标系混用 + 初始化时序 → 白屏/画面全无

### 根因（两处叠加，造成"完全加载不出来"）
1. **坐标系混用**：`cellWRef`（250-251 行）初值用 `LOGIC_W/COLS`（71px），`setupCanvas`（304-305 行）又改成**实际像素** `w/COLS`（手机上 40px）；而**绘制/碰撞逻辑大量用 `LOGIC_W/COLS`**（607-609、620+ 行），两套格子尺寸不一致 → 放置位置、爆炸范围、绘制位置全部错位。
2. **初始化时序**：`setupCanvas` 只在 `phase==='playing'` 时于 `requestAnimationFrame` 回调里执行（1081-1092 行）。若进入 playing 首帧容器尚未布局（字体加载、父容器动画、iOS 工具栏收起），`rect.width` 可能为 0 → `w=0` → **canvas 0×0，画面全白**；且没有 ResizeObserver 兜底，只有 window resize 监听（1094-1098），手机浏览器地址栏收起/展开会触发但时序不稳。

### 修复方案
```ts
// 1) 统一坐标系：全部走逻辑坐标 LOGIC_W/LOGIC_H，删掉 cellWRef/cellHRef 实际像素版本，
//    或统一为 scale 换算；不要"逻辑 + 实际"两套并存。
// 2) 用 ResizeObserver 替代/补充 window resize：
useEffect(() => {
  if (phase !== 'playing' || !containerRef.current) return;
  const ro = new ResizeObserver(() => setupCanvas());
  ro.observe(containerRef.current);
  return () => ro.disconnect();
}, [phase, setupCanvas]);
// 3) setupCanvas 兜底：rect.width 为 0 时用 window.innerWidth 或默认 360，避免 0×0 白屏：
//    const w = Math.max(Math.min(rect.width || window.innerWidth || 360, 640), 240);
```

## 问题 3【P1】横版游戏在手机竖屏下画面过小（PVZ 最典型）

### 根因
PVZ 是 9:5 横版布局（`LOGIC_W=640, LOGIC_H=356`）。手机竖屏 360px 宽 → 画面仅 **360×200px**，屏幕其余空间全空 → "画面很小很辣鸡"。植物卡片栏（1216-1253 行）56px 高的横排在 200px 画布下方，手指操作空间极窄。

### 修复方案（选一或组合）
- **方案 A（推荐）横屏体验**：进入 PVZ/Aircraft/横版游戏时检测 `window.innerHeight < window.innerWidth`（横屏）。若不是横屏，显示全屏"请横持手机"提示层（大箭头 + 旋转动画），检测到横屏后自动进入；配合问题 4 的全屏降级。
- **方案 B 竖屏重排**：竖屏下把植物卡片栏改为**右侧竖向滚动栏**（宽 ~88px），画布占左侧剩余宽度；顶部工具栏压缩高度；`max-width` 放宽到容器全宽。
- **通用**：canvas 最大化时兼顾高度，`displayW = Math.min(containerW, LOGIC_W, containerH * (LOGIC_W/LOGIC_H))`，防止横向撑满但纵向溢出。

## 问题 4【P1】iOS Safari 全屏按钮无效（`GamePlayer.tsx`）

### 根因
`GamePlayer.tsx` 37-47 行用 `containerRef.current.requestFullscreen()` + `screen.orientation.lock('landscape')`。**iPhone Safari 不支持普通元素的 Fullscreen API（仅 video 可用），也不支持 orientation.lock** —— 方法调用静默失败（被 catch 吞掉），手机上全屏按钮点了没反应，游戏只能在页面内小区域玩。

### 修复方案
```ts
const isIOS = /iphone|ipad|ipod/i.test(navigator.userAgent);
const canFullscreen = typeof document.documentElement.requestFullscreen === 'function';

const toggleFullscreen = async () => {
  if (!isIOS && canFullscreen) {
    await containerRef.current?.requestFullscreen();
    try { await (screen.orientation as any).lock('landscape'); } catch {}
  } else {
    // iOS 降级：引导横持 + CSS 撑满视口（无浏览器 UI 干扰）
    setIosHint(true);   // 显示"横持手机体验最佳"提示
  }
};
```
降级提示层：居中"请将手机横过来，体验更佳"，带旋转手机动画（CSS keyframes）。

## 问题 5【P1】viewport 未配置：刘海屏遮挡 + 双指缩放干扰

### 根因
`src/app/layout.tsx` **没有 `export const viewport`**。Next.js 默认 viewport 不含 `viewport-fit=cover`（iPhone 刘海屏内容被传感器区域遮挡）和 `user-scalable=no`（游戏中双指缩放/双击缩放干扰操作）。

### 修复方案
`src/app/layout.tsx` 加：
```ts
import type { Viewport } from 'next';
export const viewport: Viewport = {
  width: 'device-width',
  initialScale: 1,
  maximumScale: 1,
  userScalable: false,
  viewportFit: 'cover',   // 关键：iPhone 安全区适配
};
```
游戏区域容器加 `style={{ touchAction: 'none' }}`（PVZ 已有，其余游戏 canvas 需统一加上，见问题 8 模板）。

## 问题 7【P2】性能：低端手机卡顿（"加载不出来"的另一层）

### 根因
- **dpr 无上限**：`devicePixelRatio` 在安卓旗舰/iPhone 是 3 → canvas 缓冲 3 倍像素，`fillText` 全量重绘每帧，低端机直接掉帧到"假死"。
- PVZ 每帧几十~上百次 emoji `fillText`（阳光、植物、僵尸、豌豆），无离屏缓存。

### 修复方案
```ts
const dpr = Math.min(window.devicePixelRatio || 1, 2);   // 上限 2，手机上足够清晰
```
- 静态元素（植物 emoji）用离屏 canvas 缓存：`offscreen` 画一次，每帧 `drawImage` 即可。
- 绘制循环加**节流/暂停**：`document.visibilitychange` 隐藏时 `cancelAnimationFrame`，回到前台再开。
- `deltaMs` 已做 50ms 上限（PvzGame 538 行），保留；其余游戏如无此保护需补（防止切后台后时间跳跃）。

## 问题 8【P3】统一响应式画布规范（建议抽公共组件）

给所有 canvas 游戏提供统一模板（新游戏直接复用），一次解决缩放/触摸/性能：

```tsx
// components/games/ResponsiveCanvas.tsx（示例）
'use client';
export function useResponsiveCanvas(
  canvasRef: React.RefObject<HTMLCanvasElement | null>,
  containerRef: React.RefObject<HTMLDivElement | null>,
  LOGIC_W: number, LOGIC_H: number, maxW = 640, maxDpr = 2
) {
  useEffect(() => {
    const canvas = canvasRef.current, container = containerRef.current;
    if (!canvas || !container) return;
    const setup = () => {
      const dpr = Math.min(window.devicePixelRatio || 1, maxDpr);
      const cw = container.clientWidth || window.innerWidth || 360;
      const displayW = Math.max(Math.min(cw, maxW), 240);
      const displayH = displayW * (LOGIC_H / LOGIC_W);
      const scale = displayW / LOGIC_W;
      canvas.width = displayW * dpr;
      canvas.height = displayH * dpr;
      canvas.style.width = `${displayW}px`;
      canvas.style.height = `${displayH}px`;
      const ctx = canvas.getContext('2d');
      ctx?.setTransform(dpr * scale, 0, 0, dpr * scale, 0, 0);
      scaleRef.current = scale;   // 供绘制循环/坐标换算使用
    };
    setup();
    const ro = new ResizeObserver(setup);
    ro.observe(container);
    return () => ro.disconnect();
  }, []);
}
```
**核对清单（逐游戏自查）**：
- [ ] 绘制循环每帧 `setTransform(dpr*scale)`，不是只 `setTransform(dpr)`
- [ ] 触摸/点击坐标换算用 `(client - rect) / rect * LOGIC`，与绘制同一坐标系
- [ ] `touchAction: 'none'` + 无 `user-select`
- [ ] `ResizeObserver`（不是只有 window resize）
- [ ] dpr 上限 2、逻辑宽上限（min(容器宽, LOGIC_W)）
- [ ] 横版游戏（PVZ/Aircraft/Adventure/Parkour/Breakout/TowerDefense）横屏提示或竖屏重排
- [ ] 全屏按钮 iOS 降级可用
- [ ] 触控目标 ≥44px
- [ ] 无横向滚动溢出（body 不出现水平滚动条）

## 验收标准（修完必须逐条过）

1. **iPhone Safari + 安卓 Chrome 实测 PVZ**：9 列 5 行完整可见、无裁剪；能选植物、种到任意格子；阳光可点收集；僵尸从右侧完整进入画面；无白屏。
2. 所有 canvas 游戏：画面不超过屏幕宽、不变形、清晰度正常（dpr 处理正确）、横屏不溢出。
3. 横版游戏：横持有提示；全屏在 iOS 有降级路径，不再"点了没反应"。
4. 双指缩放不改变游戏画面（viewport + touchAction）。
5. 低端机（dpr=3 安卓中端）PVZ 流畅无卡死；切后台再回来游戏继续正常。
6. 电脑端回归：所有游戏与原行为一致（缩放因子 1:1 时不改逻辑）。
