# 数字花园 · 后续开发路线图（v3 之后）

> 本文档写给接手开发的 agent。目标：在现有技术栈（Next.js 16 App Router + React 19 + shadcn/ui + Tailwind 4 + Cloudflare Workers + Neon PostgreSQL + Prisma）上，把「个人数字花园」从一个单机玩具升级为**体验完善、有留存、可分享**的个人数字空间。
> 所有方案已考虑 Cloudflare 免费层与 Neon 免费层约束。**移动端优先**（用户主场景是手机）。

---

## 〇、定位与设计原则

**定位**：个人数字花园 = 博客 + 游戏厅 + 工具箱 + 留言板，核心是"个人内容的家"。

**四条原则（所有功能必须遵守）**：
1. **移动端优先**：一切新功能先保证手机可用（触控 ≥44px、竖屏可用、不溢出）。
2. **游戏即流量**：游戏是用户停留最久的模块，所有增强围绕"让人多玩一次"（每日挑战、排行榜、成就）。
3. **零成本运行**：只用 Cloudflare/Neon 免费层，任何新依赖必须是免费的（或免费额度够用）。
4. **小步可回滚**：每个功能独立成版（版本归档机制已建立：`versions/vN_日期/`），每期可独立部署验证。

**免费层红线（规划时已考虑，实现时勿越）**：
- Workers：10 万请求/天（够用，但避免高频轮询 API）
- Neon：0.5GB 存储 + 190 计算时/月（**勿存大字段**，如 base64 图片；图片走 R2）
- R2：10GB 存储 + 100 万读/天（图片/头像/关卡资源的家）
- Cron Triggers：免费版每日次数有限，定时任务少而精

## 一、现状盘点

**已有能力**：
- 内容：博客（列表/详情/编辑器 + 管理后台 AdminPanel）、日记（Diary 表）
- 游戏：15 款（贪吃蛇/2048/俄罗斯方块/飞机大战/打砖块/冒险勇士/五子棋/消消乐/迷宫/扫雷/PVZ/保卫萝卜/Flappy/跑酷/记忆翻牌），游戏分数有本地+云端记录（GameScore/UserScore）
- 工具：8 个（取色器/倒计时/日记/密码生成/番茄钟/随机名言/待办/天气）
- 社交：留言板（Message 表）、用户系统（注册/登录/token）
- 系统：访问统计（SiteStat）、站点配置（SiteConfig）

**核心短板（本轮必须解决）**：
1. **手机端游戏体验差**（另有一份《手机端游戏体验整改方案.md》，先行落地）
2. **游戏没有留存机制**：分数是孤立的数字，无排行榜、无成就、无每日挑战 → 玩一次就腻
3. **博客没有互动**：无标签、无搜索、无评论、无阅读量
4. **无头像/无用户画像**：留言和评论无头像，用户系统只有 token
5. **无 PWA**：不能"添加到主屏幕"，无离线缓存，体验像网页不像应用

## 二、游戏扩展方向（新增游戏，按实现难度分级）

### 2.1 快速取胜（Easy，2~3 天/款，canvas 复用现有模板）
| 游戏 | 玩法要点 | 实现提示 |
|---|---|---|
| **数独** | 9×9 标准数独，难度 3 档，错误高亮 | 生成算法：回溯 + 随机挖空；手机端 9×9 格子正好触控友好 |
| **华容道/数字华容道** | 经典滑块拼图（15-puzzle），步数计时 | 网格渲染 + 滑动/点击两种控制，复用 Memory 的网格逻辑 |
| **黑白棋（奥赛罗）** | 双人同屏或 vs 简单 AI | 最小可用 AI：贪心 + 1 层搜索，避免复杂 minimax |
| **数织（Nonogram）** | 行列线索推理填色 | 生成器较易（从图案反推线索），判定简单 |
| **纸牌接龙（Klondike）** | 经典单机纸牌 | 拖拽 + 点击移动双模式，注意触控拖拽手感 |

### 2.2 中期增强（Medium，1 周左右/款）
| 游戏 | 玩法要点 | 实现提示 |
|---|---|---|
| **弹幕射击（增强飞机大战）** | 敌人弹幕、Boss、道具掉落 | 在 AircraftGame 上扩展：弹幕发射器 + Boss 状态机 |
| **坦克大战** | 双人同屏（一机双人：方向键 vs WASD） | 本地双人是移动端杀手级功能；需按键面板 |
| **无尽跑酷 v2** | 在 ParkourGame 上加：皮肤、金币商城、难度曲线 | 强化已有游戏比新写更划算 |
| **音乐节奏（简化版）** | 下落音符点击 | 用 WebAudio 生成简单音效 + 音符下落，注意 iOS 音频解锁 |

### 2.3 长期旗舰（Hard，跨版本）
| 功能 | 说明 |
|---|---|
| **双人同屏对战大厅** | 贪吃蛇/五子棋/坦克大战同屏对战 + 本地热座（hot-seat） |
| **游戏关卡编辑器** | 迷宫/跑酷支持用户自建关卡，存 R2/Neon，可分享链接 |

> 决策建议：**优先做"数独 + 黑白棋 + 弹幕增强 + 无尽跑酷 v2"**，四款覆盖益智/策略/动作三大类，且难度可控。

## 三、功能扩展方向（游戏之外）

### 3.1 留存与激励（P0，最高价值）
1. **全局排行榜**：每个游戏一个排行榜（按分数/时间），显示"我的排名"，新表 `GameLeaderboard` 或复用 GameScore 加 `userId` 关联。移动端首页可展示"今日最佳"。
2. **成就系统**：新表 `Achievement` + `UserAchievement`。示例成就：玩 10 款不同游戏/单局 10000 分/连续 7 天登录/通关任意困难难度。成就弹窗 Toast + 个人页徽章墙。
3. **每日挑战**：每天一个游戏一个固定种子/固定目标（如"今日贪吃蛇目标 300 分"），用日期做 seed，达成打勾，连续天数 streak 记录（存 `DailyChallenge` 表或 SiteConfig）。
4. **访客署名**：未登录也能玩，但分数带"游客"标记；登录后分数归属用户。

### 3.2 内容与社交（P1）
5. **博客增强**：标签（文章多对多，新表 `Tag`/`ArticleTag`）、站内搜索（Neon `ILIKE`，数据量小够用）、**阅读量**（Article.viewCount 已有，点击+1 需防刷：session 去重）、目录 TOC（博客详情生成锚点目录）。
6. **评论系统**：留言板升级为**文章评论区**（新表 `Comment`：articleId/nickname/content/parentId，支持楼中楼）。留言板保留为"随便聊聊"。头像用 **DiceBear API（免费）** 或本地生成 SVG 头像，避免上传。
7. **友链页**：`FriendLink` 表，站长维护，展示交换友链。
8. **访客足迹**：统计每个页面访问（SiteStat 扩展或新表 `PageView`），首页展示"最热文章/最热游戏"。

### 3.3 工具箱扩展（P1，低成本高感知）
新增工具（每个都是独立小组件，1 天/个）：
- **JSON 格式化/校验**（粘贴即格式化，错误定位）
- **正则测试器**（高亮匹配 + 分组展示）
- **二维码生成**（用 `qrcode` 库前端生成，无需后端）
- **单位换算器**（长度/温度/数据量）
- **Markdown 预览器**（与博客编辑器复用渲染）
- **IP/UA 查询**（后端读请求头返回，简单）
- **作息表/喝水提醒**（localStorage + 通知 Notification API，注意 iOS 通知限制）

### 3.4 系统与体验（P1-P2）
9. **PWA**：`next-pwa` 或手写 manifest + service worker，支持"添加到主屏幕"（图标：用现有 favicon/Logo 生成 192/512 图标）、离线壳缓存、安装提示横幅。**Workers 上 PWA 完全可行**（静态资源走 CDN）。
10. **暗色模式完善**：next-themes 已有，检查各游戏 canvas 在暗色下的对比度（PVZ 草坪/格子线）。
11. **后台管理增强**：AdminPanel 增加——留言管理（删除/屏蔽）、用户列表、统计报表（近 7 日访问折线，用 recharts 已有依赖）、站点配置可视化编辑（SiteConfig 表已存在，把 site title/description 做成可配置）。
12. **数据导出**：一键导出我的博客/日记/留言为 Markdown/JSON（后台按钮，流式下载）。

## 四、优化方向（技术层面）

### 4.1 移动端（承接整改文档，P0）
- 统一响应式画布模板（`useResponsiveCanvas`：逻辑缩放、dpr 上限 2、ResizeObserver、touchAction）
- 横版游戏横屏提示 + iOS 全屏降级
- 触控目标 ≥44px、防双指缩放（viewport `user-scalable=no, viewport-fit=cover`）

### 4.2 性能（P1）
- **游戏组件懒加载**：`GameHall` 只渲染入口卡片，点进游戏时 `next/dynamic` 按需加载游戏组件（当前 15 款游戏代码全量打进首屏 bundle，是最大的性能浪费）。预计首屏 JS 减 50%+。
- **图片优化**：博客配图用 `next/image` + R2 托管（自适应尺寸/格式）。
- **缓存**：开启 OpenNext 的 **R2 incremental cache**（`open-next.config.ts` 里 `r2IncrementalCache`，R2 免费 10GB）——博客详情页等可缓存路由大幅提速；API 加 `Cache-Control` 头（短 TTL）。
- **首页**：SSG 静态化（现在 `/` 是静态 ○，保持），动态数据用客户端 fetch + 骨架屏。

### 4.3 安全与稳定（P1）
- **留言/注册防刷**：简单速率限制（按 IP，Workers 上用 KV 或内存 Map + 限时；Neon 记录失败次数）；验证码可选（`hcaptcha` 免费）。
- **XSS 防护**：博客/留言渲染用 `react-markdown` 时确认 `rehype-sanitize` 已启用；富文本编辑器（@mdxeditor/editor）输出需净化。
- **日志**：API 错误写 `ErrorLog` 表（Neon），管理后台可查；避免 console 裸奔。

### 4.4 架构演进（P2）
- **游戏配置化**：游戏列表从 GameHall 硬编码数组 → 数据库 `Game` 表驱动（图标/名称/描述/入口），后台可上下架。
- **多语言**：`next-intl` 已装，暂缓（个人站中文为主），但文案抽常量便于未来扩展。
- **定时任务**：Cron Triggers 每日重置每日挑战、清理过期访客会话（免费额度内，1-2 个 cron 足够）。

## 五、数据模型演进（Neon 新增表规划）

| 新表 | 用途 | 关键字段 | 关联 |
|---|---|---|---|
| `Tag` / `ArticleTag` | 文章标签 | name / articleId | Article 多对多 |
| `Comment` | 文章评论 | articleId, nickname, content, parentId, createdAt | Article |
| `FriendLink` | 友链 | name, url, avatar, desc, sort | — |
| `Achievement` / `UserAchievement` | 成就定义与解锁 | code, name, desc, icon / userId, achievementId, unlockedAt | User |
| `DailyChallenge` | 每日挑战 | date, game, target, seed, completedUsers | — |
| `PageView` | 页面访问明细 | path, userAgent, ipHash, createdAt | — |
| `ErrorLog` | 错误日志 | route, message, stack, createdAt | — |
| `Game`（可选） | 游戏配置表 | key, name, desc, icon, enabled, sort | — |

> 实现注意：**模型变更一律 `npx prisma db push`**；新增表前确认 Neon 免费存储余量（0.5GB 很充裕，只要不塞大字段）。`UserScore`/`GameScore` 已有，排行榜优先复用。

## 六、分阶段路线图

### 阶段一：体验修复 + 留存地基（1~2 周）
1. 落地《手机端游戏体验整改方案》（画布缩放、PVZ 修复、iOS 全屏、viewport）——**先做**
2. 游戏组件懒加载（首屏性能）
3. 全局排行榜 + 分数归属用户（登录后）
4. 成就系统（第一批 8~10 个成就）
5. PWA 壳（manifest + 安装提示）

### 阶段二：内容与社交（2~4 周）
6. 博客：标签、搜索、阅读量、评论（含楼中楼）
7. 新增 4 款游戏：数独、黑白棋、弹幕增强、无尽跑酷 v2
8. 工具新增 4~6 个（JSON/正则/二维码/单位换算/Markdown 预览）
9. 访客足迹 + 首页"最热"模块

### 阶段三：进阶（1~2 月）
10. 每日挑战 + 连续签到（streak）
11. 双人同屏对战（贪吃蛇/五子棋热座）
12. 后台管理增强（留言管理、统计报表、配置可视化）
13. R2 图片托管 + 博客配图上传（next/image 自适应）
14. 开启 OpenNext R2 缓存 + API 缓存头

### 每阶段验收标准
- 手机（iPhone Safari + 安卓 Chrome）全功能可用，无横向溢出、无触控失灵
- 新功能有数据支撑：排行榜有真实数据、成就可解锁、评论可发布
- 部署走既有流程 `npm run deploy`，并归档 `versions/vN_日期/`
- 回归：15 款旧游戏不受影响（电脑 + 手机各过一遍）

## 七、给 agent 的执行要求

1. **每期小步**：一次只做一个功能，独立提交、独立部署、独立验证，不要"一口气全做完"。
2. **移动端优先**：每个新 UI 先用手机尺寸（375×667）自测，再适配桌面。
3. **复用优先**：canvas 用统一模板、新游戏尽量复用已有组件（网格/卡片/分数面板），不要重复造轮子。
4. **数据先行**：先定表结构再写 UI；模型变更后 `prisma db push` 并验证 API。
5. **遵守免费层**：不引入付费服务；图片走 R2；定时任务少而精。
6. **文档同步**：每个大功能完成后更新 `DEPLOY.md` 和版本归档 README。
7. **优先级冲突时**：先做"阶段一"；阶段一内部按 1→5 顺序。
8. **遇到技术坑**：参照桌面《部署避坑指南.md》和记忆库 LEARNINGS（Prisma WASM、Next16 补丁、Windows 部署等已记录）。
